# Avito Parser

E2E-клиент для последовательной обработки Avito firewallPow, QRATOR и
GeeTest. Все нужные Python-зависимости и локальная библиотека `GeekedTest`
входят в репозиторий.

## Поиски на Авито: по ссылке, с наблюдением и Telegram

Нужен [uv](https://docs.astral.sh/uv/). Все команды — из папки проекта.

**Проще всего — меню:** `uv run python avito.py` без параметров. Дальше всё
выбирается цифрами: вставить ссылку, собрать, следить, открыть таблицу,
подключить Telegram. Ctrl+C во время сбора или наблюдения возвращает в меню.
Команды ниже — то же самое по отдельности.

## Создание поисков и готовые режимы в Telegram

### Режим «Все iPhone»

В Telegram: `/start` → **🚀 Готовые режимы** → **📱 Все iPhone · вся Россия** →
**▶ Запустить все iPhone**. Режим получает актуальные модели из фильтров Авито
и обходит каждую отдельным запросом с фильтрами Apple и модели. Внутренние
запросы хранятся в `data/iphone-mode/`, не появляются в «Мои поиски» и не
изменяют пользовательские поиски. Режим и обычное наблюдение используют
один рабочий процесс: перед переключением остановите текущее наблюдение.

Первый проход каждой модели запоминает текущие объявления и собирает цены;
уведомления поступают о новых публикациях последующих проходов. Кнопка
**Найденные выгодные** показывает до десяти предложений из последних проверок,
включая первоначальный сбор. Наличие товара проверяйте по ссылке.
Цены сравниваются по модели из каталога и памяти, минимум по трём подходящим
объявлениям частных продавцов. Неисправные устройства и аксессуары исключаются.
Неизвестная память не получает оценку; настройка 15%/25% исключает предложения
без оценки. Порог меняется кнопкой и применяется при обработке следующей модели.

**Статус обхода** показывает прогресс, последнюю успешную проверку и очередь
доставки. **Проверка моделей** показывает время проверки каждой модели, ошибки
и число групп с оценкой. Список моделей обновляется раз в сутки.
Режим читает две новейшие страницы на модель за проход, с паузами около
30 секунд между запросами. При десятках моделей полный обход занимает
десятки минут, а при ограничениях доступа — дольше. Это мониторинг новых
публикаций всех доступных моделей, не выгрузка всей истории Авито; при высокой
скорости публикаций часть объявлений между обходами может быть пропущена.
Режим возобновляется после перезапуска сервера, если был запущен и не остановлен
кнопкой. Очередь уведомлений переживает перезапуск. Новые режимы ПК и ноутбуков
управляются через то же меню.

### Режимы компьютеров и ноутбуков

В Telegram выберите **🚀 Готовые режимы → 🖥️ Готовые ПК** или
**💻 Ноутбуки**. В карточке каждого режима можно задать максимальную цену
числом (0 — без лимита), выбрать все новые подходящие объявления или скидку
от медианы на 15%/25%, запустить обход, посмотреть статус и найденные предложения.
Сначала собирается база похожих объявлений; уведомления идут о новых.
Бюджет ограничивает присылаемые объявления и не ограничивает цены в выборке
для сравнения. Режим ПК обходит восемь поисковых направлений, ноутбуки —
18 семейств. Из одной широкой выдачи все объявления Авито получить нельзя.

Для ПК сравнение требует распознанных процессора, ОЗУ и видеокарты; объявление
без видеокарты может прийти при выборе «Все», но будет помечено без надёжной
оценки цены. Объявления без указанной цены не присылаются. Процессоры Intel
с суффиксами F, K, KF и T распознаются и сравниваются в отдельных группах.
Для ноутбуков сравниваются модель, процессор, память, накопитель
и графика. Если характеристик или аналогов мало, процент скидки не показывается.
Оценка строится по ценам объявлений и не подтверждает техническое состояние
товара. В уведомлении указываются основание сравнения и признаки, которые
стоит проверить вручную. Объявления о скупке, запчастях и явно неисправных
устройствах отсекаются по тексту; скрытые дефекты распознать нельзя.

Токен Telegram настраивается **один раз на компьютере** через
`uv run python avito.py telegram setup`. При смене токена используйте
`uv run python avito.py telegram setup --new-token`. Не отправляйте токен
боту или в чат. Дальнейшее управление режимами, лимитами и поисками —
через кнопки Telegram. На этом ПК для сервера также настроено задание Windows
`AvitoParserBot`; если оно остановлено, запустите его через планировщик задач
или PowerShell: `Start-ScheduledTask -TaskName AvitoParserBot`.

### Собственный поиск

Отправьте `/start`, нажмите **➕ Добавить поиск** (или `/new`) и выберите
готовые ПК, ноутбуки, iPhone или мониторы. Затем напишите модель/запрос,
максимальную цену и город либо **Вся Россия**. Символ `-` означает стандартный
запрос категории или отсутствие ограничения цены на соответствующем шаге.

Бот проверяет выдачу Авито и показывает регион, запрос, цену, количество и
примеры объявлений. Только кнопка **Сохранить поиск** добавляет конфигурацию
в «Мои поиски». После этого выберите поиск и нажмите **Следить**.
Проверка зависит от доступности Авито; при сохранении выдача проверяется повторно.
«Отмена» или `/start` сбрасывает незавершённый мастер. После перезапуска
сервера незавершённый мастер нужно начать заново; сохранённые поиски остаются.
Для этих категорий используются существующие профили оценки цены и фильтрации;
оценка зависит от количества и сопоставимости собранных объявлений.

### Управление через Telegram на Windows

В карточке поиска кнопка **⚙️ Уведомления** позволяет выбрать все подходящие
объявления или предложения дешевле медианы минимум на **15% / 25%**.
Перед изменением остановите наблюдение, затем запустите его снова.
«Все» сохраняет фильтры категории, продавца и состояния; ноутбуки без
сопоставимой выборки по-прежнему не проходят профиль `laptop-deals`.

Во время наблюдения цены рассчитываются по отдельной выборке до трёх
новейших страниц с теми же запросом, категорией и регионом, но без `pmin/pmax`.
Она хранится в `market-reference.json`, кэшируется на шесть часов и не
попадает в список просмотренных объявлений. Если обновление не удалось,
оценка отключается до успешного обновления. Порог скидки применяется к
числовым ценам; неизвестная оценка и явно неисправный товар его не проходят.
Уведомление показывает количество объявлений в расчёте. Это ограниченная
выборка цен предложений, а не оценка завершённых сделок или всей площадки.
Таблица Excel пока сохраняет прежний расчёт по собранной выдаче.

Уведомления наблюдения сохраняются отдельно для каждого поиска в
`pending-alerts.sqlite3` до отправки Telegram. При сетевой ошибке очередь
повторяется в следующем цикле и после повторного запуска этого поиска.
Токен в очереди не хранится; сообщения привязаны к исходному Telegram-чату.
После успешной отправки сохраняется ID объявления для защиты от повторов.
При аварии между приёмом сообщения Telegram и записью подтверждения на диск
возможен дубль: доставка не имеет гарантии «строго один раз».
Остановленный или удалённый поиск свою очередь не отправляет.

Профиль готовых ПК исключает явно неисправные и некомплектные сборки.
Для распознаваемых серий ноутбуков на Intel/AMD сравнение требует указанных
в заголовке модели CPU, памяти/накопителя в формате `8/256` и графики
(например, `ThinkPad T480 i5-8250U 8/256 UHD 620`). Разные комплектации
сравниваются отдельно. Неполные заголовки не получают оценку; это ограничение
текущего распознавания. Правила распознавания MacBook сохранены.

Дважды щёлкните `start_bot.cmd` в папке проекта. Откроется обычное меню
«АВИТО-ПОИСКИ», а Telegram-сервер запустится автоматически: через задание
Windows `AvitoParserBot`, если оно установлено, либо отдельным фоновым
процессом. Если токен ещё не введён, выберите в меню пункт **Telegram** и
подключите бота; сервер запустится после успешной настройки. Повторное
подключение через меню перезапустит сервер с новым токеном.

В Telegram отправьте **своему** боту `/start`. Сервер принимает
команды только из чата, который был сохранён при настройке; токен бота в чат
не отправляйте. Ctrl+C во время длительного действия в старом меню возвращает
к выбору действия; выход из меню не останавливает Telegram-сервер. Если нужно
остановить сервер из задания Windows, используйте планировщик задач.
Одновременно запускать старый `watch` для тех же поисков нельзя.
После `/start` появятся пять кнопок: готовые режимы, мои поиски, добавление
поиска, наблюдение и главное меню. В «Моих поисках» находятся готовые поиски
и выбор нескольких поисков для слежения. В «Добавить поиск» можно выбрать
категорию или кнопку «По ссылке»; затем пришлите ссылку отдельным сообщением.
В «Наблюдении» показывается состояние и, когда оно запущено, кнопка остановки.
«Главное меню» отменяет текущий ввод. Старые сообщения с прежними кнопками
продолжают работать. Команды ниже остаются доступными как дополнительный способ.
Ответы на команды и готовые таблицы сохраняются в локальной очереди, если
Telegram временно недоступен, и отправляются после восстановления связи.

- `/presets` — добавить готовый поиск по всей России: iPhone 11 Pro, все
  iPhone, товары для компьютера, системные блоки до 9 000 ₽, ноутбуки,
  мониторы.
- `/searches` — список поисков и кнопки для каждого: следить, собрать,
  получить Excel, удалить. Удаление требует подтверждения и оставляет
  ранее собранные данные на диске.
- `/select` — отметить несколько поисков кнопками и начать наблюдение за ними.
- `/add <ссылка Авито>` — добавить собственный поиск.
- `/watch <имя> [имя...]`, `/stop`, `/status`, `/test` — управление наблюдением.

Поиск iPhone 11 Pro сравнивает цены внутри групп по объёму памяти. Таблица
показывает медиану и процент отклонения от неё; уведомления тоже содержат
сравнение, когда есть достаточно сопоставимых объявлений. Это оценка по
собранной выдаче, а не гарантия качества товара или выгодности сделки.
Для ноутбуков сравнение делается по распознанной модели и комплектации, когда
в сохранённой выдаче хватает недавних объявлений. Если данных мало или модель
нельзя надёжно определить по заголовку, процент не рассчитывается и уведомление
о «выгодной цене» не отправляется. При недостатке объявлений частных продавцов
берётся медиана всех продавцов, что указывается в уведомлении. Старые объявления
старше 14 дней в расчёт не входят.
Для системных блоков до 9 000 ₽ сравнение цены работает при указанных
поколении процессора и объёме ОЗУ. Если видеокарта указана, сравниваются
только объявления с той же моделью видеокарты. Если она не указана,
показывается приблизительный ориентир по процессору и ОЗУ с предупреждением.
ПК с монитором сравниваются отдельно от объявлений без указанного монитора.
Медиана считается по минимум трём недавним объявлениям частных продавцов
с такой же группой характеристик в сохранённой выдаче этого поиска.
Если характеристик или сопоставимых цен недостаточно, процент не выводится.
Поскольку поиск ограничен ценой 9 000 ₽, это сравнение только с объявлениями
внутри бюджета, а не оценка всего рынка.

**1. Добавить поиск по ссылке.** Откройте Авито в браузере, выставьте город,
категорию и фильтры, скопируйте ссылку из адресной строки:

```bash
uv run python avito.py add "https://www.avito.ru/kazan/telefony/mobilnye_telefony/apple/iphone_15-ASgBAgICA0SywA2SoO0RtMANzqs5sMENiPw3"
```

Программа сама определит город, категорию и фильтры, проверит поиск на Авито
и покажет, что поняла: сколько объявлений, какие фильтры применились, примеры
заголовков. Имя поиска берётся из ссылки (`iphone_15-kazan`), своё — `--name`.
Только проверить, не сохраняя, — `--dry-run`. Квартиры, комнаты, дома и
другая недвижимость получают обработку `realty-owner`, всё остальное — `goods`.

**2. Собрать все объявления** (до 30 страниц, ~15 минут; прерванный сбор
продолжается с той же страницы):

```bash
uv run python avito.py scan iphone_15-kazan
```

**3. Подключить Telegram** (один раз): создайте бота у @BotFather, затем

```bash
uv run python avito.py telegram setup
```

Токен вводится в терминале и хранится только на этом компьютере
(`data/telegram.json`). Проверка: `uv run python avito.py telegram test`.

При локальных тестах все пути к данным и настройкам, включая
`bot_jobs.WATCH_TARGETS`, должны указывать на временный каталог. Проверяйте
отправку уведомлений через тестовый отправитель без сообщений в рабочий чат:
сообщение должно быть сохранено до отметки объявления как просмотренного.
При проверке оценки цены отделяйте текущую выдачу наблюдения от справочной
выборки; объявления из справочной выборки не должны попадать в список
просмотренных.

**4. Следить за новыми объявлениями** (остановить — Ctrl+C):

```bash
uv run python avito.py watch iphone_15-kazan
```

Новые объявления печатаются в терминале и уходят в Telegram. При запуске
программа молча запоминает текущую выдачу и дальше присылает только то, что
появилось после запуска и было создано впервые: перед уведомлением программа
открывает страницу объявления, и если у него есть просмотры с прошлых дней
(старое переопубликованное), уведомления нет. Объявление также должно было
попасть в выдачу не раньше 3 часов назад — с запасом на модерацию Авито. По товарам —
только частные лица из города поиска: без компаний, без «частников» со 100+
закрытыми объявлениями и без доставки из других городов. По квартирам —
только собственники. В таблице остаются все. В файле поиска это меняется
полями `"fresh_hours": 3`, `"alert_sellers": "all"` (все продавцы) и
`"new_only": false` (присылать и переопубликованные). Можно следить за несколькими поисками
сразу: `watch поиск1 поиск2`.

**Прочее:** `avito.py list` — какие поиски есть; `avito.py table <поиск>` —
таблица Excel в `output/`; `uv run python html_view.py <поиск>` — страница с
фильтрами для квартир.

Темп — около 30 секунд между запросами; после капчи открывается новая сессия,
капча не решается. Данные поисков лежат в `data/searches/<имя>/`, таблицы — в
`output/`; обе папки исключены из Git. Авито отдаёт не больше 30 страниц
(1 500 объявлений) на поиск; больший рынок делите на несколько поисков
(например, по объёму памяти).

### Для ИИ-агента

- Флаг `--json` ставится перед командой: `uv run python avito.py --json add "<ссылка>"`.
  Каждое событие — одна строка JSON с полем `event`: `ADDED`, `SEARCH`, `SCAN`,
  `PAGE`, `TABLE`, `WATCH`, `ALERT`, `SESSION-RESET`, `IP-BLOCK`, `ERROR`, `FATAL`.
- Ошибка — код выхода 1 и событие `FATAL` с полем `error`.
- `add` не спрашивает подтверждений; `telegram setup` интерактивный (токен и
  /start делает человек), поэтому его запускает пользователь.
- `scan` и `watch` работают долго; `watch` не завершается сам. Не запускайте два
  `watch` по одному поиску одновременно: они пишут в одну базу.
- `watch` при запуске молча запоминает текущую выдачу (событие `PRIMED`);
  уведомления — только о появившемся после запуска.
- Один поиск может наблюдаться только одним локальным процессом. Второй `watch`
  завершится с понятной ошибкой, чтобы не повредить базу и не продублировать
  уведомления. Запуск второго Telegram-сервера тоже блокируется.

`limit_probe.py` — эксперимент для замера лимитов Авито на своём IP.

## Двушки в Петербурге от собственников

`apartments.py` ищет на Авито двухкомнатные квартиры на продажу в
Санкт-Петербурге (все районы, вторичка и новостройки, любая цена) у продавцов
с отметкой «Частные» и сохраняет таблицу Excel в `output/`.

```bash
uv sync
uv run python apartments.py
```

Лист «Собственники» — объявления без признаков агента; сначала новые, затем
самые свежие. Лист «Отсеяно — агенты» — что убрано и почему, чтобы фильтр
можно было проверить глазами.

Как отсеиваются агенты:

- Авито сам подписывает продавца «Агентство» / «Компания» — отсеивается;
- в описании фразы агентства: «наше агентство», «эксклюзивные права»,
  «бесплатное сопровождение сделки», «трейд-ин», номер объекта в базе и т. п.;
- фразы с отрицанием («эксклюзивный договор не подписываю», «комиссию не
  плачу») агентскими не считаются;
- значок Авито «Собственник / Проверено в Росреестре» не учитывается: он
  бывает и на объявлениях агентств;

## Файл

## E2E: `get` → `verify`

`main.py` получает свежий `pow_challenge` из HTTP 439, затем выполняет
`POST /get` и `POST /verify`. JWT из ответа первого PoW-запроса передаётся в
уже реализованную `build_verify_payload()` из
`firewallpow_payload_reference.py`; она возвращает оригинальный JWT и
найденный для него `nonce`.

Главный запрос — `GET /web/1/js/items` для `categoryId=24` (квартиры),
`locationId=653240` (Санкт-Петербург), «Купить», 2 комнаты, продавцы
«Частные». Все параметры заданы константами в `ITEMS_QUERY_PARAMETERS`, а `p`
последовательно меняется от 1 до последней страницы (не больше 100).
Каждый запрос содержит `X-Source: client-browser`. Challenge всегда берётся
из текущего ответа, а cookies ведёт одна внутренняя HTTP-сессия.

Перед первым items-XHR та же сессия выполняет обычный document GET страницы
каталога с browser navigation-заголовками. Bootstrap проходит выбранные
PoW/QRATOR/Gee-ветки, пока не получит HTTP 200, и сохраняет серверное состояние
и все установленные Avito cookies. Наличие `buyer_location_id`, `luri`, `sx`
диагностируется отдельно: сервер может установить их только первым успешным
items-ответом. После bootstrap начинается цикл `p=1` … до последней страницы.

```bash
uv run python main.py
```

Cookies из `Set-Cookie` первого запроса и `/get` остаются в cookie jar сессии и
автоматически передаются на следующие запросы.

После успешной PoW-проверки либо ответа HTTP 200 скрипт в той же сессии делает
items-XHR `p=1`, `p=2`, … пока `p × itemsOnPage < totalCount`. Для каждого сразу выводится HTTP-статус.
Из успешного JSON читаются верхнеуровневые `count`, `totalCount`,
`totalElements`, `mainCount`, `itemsOnPage`. В INFO рядом со статусом
выводятся `totalCount`, `itemsOnPage` и стабильный BLAKE2b-128 хеш полного
массива `catalog.items`; хеш подходит для быстрой проверки уникальности
страниц.
Между последовательными страницами выдерживается 2 секунды. При первом HTTP 403, 429 или 439
проход останавливается, ответ классифицируется и соответствующая защитная
ветка выполняется в той же сессии. После успешной PoW/Gee-проверки повторяется
тот же `p=N`, на котором появилась защита, и после его HTTP 200 цикл
продолжается с `p=N+1`. QRATOR также повторяет ровно исходный защищённый GET.

Body ответа читается целиком потоково. При обрыве выполняется до трёх попыток
с таймаутом 10 секунд. Если curl сообщает ошибку закрытия соединения уже после
полностью полученного HTML с `</html>`, сохранённый body принимается без
повторной загрузки. Proxy-переменные окружения намеренно игнорируются:
основной flow и вложенный GeeTest solver работают через прямое соединение.

При HTTP 302 с заголовком `Server: QRATOR` скрипт автоматически воспроизводит
cookie-цепочку из `302.har`:

1. Из HTML извлекает и загружает same-origin fingerprint JS.
2. Загружает `/favicon.ico`, чтобы получить/обновить cookie `v`, и выдерживает
   meta-refresh интервал из HAR до отметки в одну секунду.
3. Генерирует новый `f` из `base.txt`, а `s` — из неизменного `base-s.json`.
4. Сохраняет `f` в cookie jar и отправляет `f`/`s` как multipart form-data на
   `POST /web/2/ft`.
5. Оставляет серверные `Set-Cookie` в той же сессии и сохраняет JSON-строку
   ответа `/ft` в cookie `ft` вместе с кавычками, как это делает исходный JS.
6. Отправляет пиксель `GET /web/1/u?<number>`, где `number` вычисляется точно
   как `Math.floor(Math.random() * 4294967295)`, и сохраняет его `Set-Cookie`.
7. Ждёт две секунды, затем повторяет исходный items GET с тем же URL,
   `X-Source: client-browser` и остальными XHR-заголовками.

Успешными считаются HTTP 200 от обоих служебных endpoint'ов; иначе исходный
GET не повторяется, а причина записывается в диагностический лог. Число в
`/web/1/u?<number>` передаётся без знака `=`, как в HAR и исходном bundle.
Для HTTP/TLS используется Firefox-профиль `curl_cffi`, а явные заголовки
соответствуют Firefox 152 из HAR.
OS-токен User-Agent выбирается по платформе запуска: `Windows NT 10.0` на
Windows, `X11; Linux x86_64` на Linux и macOS-токен на Darwin. Поэтому
User-Agent не противоречит сетевому стеку реальной машины.

Если источник возвращает HTTP 200, проверка не требуется. При HTTP 429 скрипт
сначала проверяет JSON на `pow_challenge`. Captcha dispatcher может прийти как
HTTP 403, так и HTTP 429; оба варианта распознаются по
`X-Firewall-Show-Captcha: true` и ссылке
`ru.avito://1/firewall/captcha/show`. Dispatcher вызывает
`/web/5/firewallCaptcha/get` и классифицирует фактически выбранный тип.
`geeTest` запускается с captcha ID, извлечённым из Avito bundle; для
HTML-ветки остаётся проверка маркеров `#geetest_captcha`, `gt4.js`,
`initGeetest4` и `captchaId`.

Для GeeTest затем выполняется `/load`. Полный объект `data` передаётся уже
реализованному solver-у из `GeekedTest`; тот формирует `w`, отправляет GeeTest
`/verify`, а полученный `seccode` передаётся в Avito
`POST /web/3/firewallCaptcha/verify`. После `verified=true` исходный GET
повторяется в той же Avito-сессии.

Если GeeTest `/verify` отвечает `result=fail`, отклонённый `lot_number`
повторно не используется. Скрипт заново выполняет исходный items GET с тем же
`p=N`, получает свежую captcha-ветку и новый `/load`, затем запускает solver
с нуля. После пяти последовательных отказов работа прекращается; ошибка
содержит тип последней задачи, `lot_number`, `result` и серверный
`fail_count`.

Avito и вся GeeTest-цепочка (`/load`, изображения и `/verify`) используют одну
`curl_cffi.Session`, один cookie jar и один сетевой маршрут. GeeTest-запросы
повторяют Firefox-заголовки из HAR (`Referer: https://www.avito.ru/`,
`Sec-Fetch-Site: cross-site`), а `firewallCaptcha/get` и
`firewallCaptcha/verify` используют постоянный Referer страницы каталога.
Ответ Avito `verified=false` также считается неудачной Gee-попыткой и
перезапускает цепочку с исходного GET, максимум пять раз подряд.
Общий предохранитель защитных переходов на одной странице равен 25 и не
мешает этим пяти попыткам, даже если между ними сервер дополнительно выдаёт
PoW или QRATOR.

Каждый captcha-flow автоматически сохраняет полные структурированные HTTP-
диагностики в `firewall-debug-responses/exchange-*.json`: method, URL,
заголовки и cookie jar до запроса, params/JSON payload, HTTP status,
заголовки, полное body и cookie jar после ответа. Артефакты создаются для защищённого page GET,
`firewallCaptcha/get`, GeeTest `/load`, GeeTest `/verify`,
`firewallCaptcha/verify` и первого повторного page GET. Файлы содержат
действующие cookies и captcha-токены, поэтому их нельзя публиковать; каталог
исключён из Git.

Живой E2E HTML- и JSON-dispatcher веток подтверждён 27–28 июля 2026 года:
свежие `firewallCaptcha/get` и GeeTest `/load` были решены локальным solver-ом,
после чего Avito принял `firewallCaptcha/verify` и вернул успешную
верификацию. Неизвестные или пока неподдерживаемые варианты сохраняются
целиком для диагностики.

HTTP 400 не считается защитной веткой: его полное тело сохраняется в
`firewall-debug-responses/page-p-N-http-400.*`, заголовки попадают в
`firewall-debug.log`, после чего цикл продолжает запрос со следующей страницы.

## Что обрабатывает код

1. Из ответа `get` получает `success.result.challenge_jwt`.
2. Декодирует JWT payload и читает `id` и `compl`.
3. Подбирает `nonce`, для которого SHA-256 от строки `id:nonce` начинается с `compl` нулей.
4. Из ответа `verify` читает `success.result.verified` и вызывает обработчик успеха только если значение истинно.

Это единственный JavaScript-ресурс в данном HAR, содержащий оба точных пути. Отдельного файла для каждого endpoint’а в архиве нет.

## Qrator `f` / `s`

Разбор формирования fingerprint-полей, сохранённого raw-текста и границы
обратного декодирования вынесены в
[`QRATOR-FINGERPRINT-ANALYSIS.md`](./QRATOR-FINGERPRINT-ANALYSIS.md).

### Генерация вариантов из decoded base

```bash
python generate_qrator_variants.py \
  --count 1000 \
  --output variants.ndjson
```

Каждая строка NDJSON содержит `f`, статичный `s`, выбранный `canvasHash` и
timestamp. Генератор:

- читает 141-компонентную основу из `base.txt`;
- ставит текущий Unix timestamp в индекс 128;
- генерирует уникальный unsigned 32-bit canvas hash для индекса 106;
- выполняет точный XTEA encode;
- один раз кодирует неизменный `base-s.json`.

Для воспроизводимой тестовой последовательности можно передать `--seed`.
Поля CPU, screen, platform и GPU независимо не перемешиваются: они связаны с
составными fingerprint hashes, и их произвольная комбинация создаёт
противоречивый профиль.
